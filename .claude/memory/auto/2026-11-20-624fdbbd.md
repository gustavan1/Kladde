## Updater signing key must be preserved across the secret move because existing installs depend on it
_security_note · 2026-11-20T10:17:38.145Z_

PR #13 notes the updater signing key must be stored in the release-signing environment unchanged, since installed copies verify updates against it.

Moving the updater signing key from a repository secret to the protected release-signing environment is only safe if the key itself is unchanged. Installed Kladde copies verify signed in-app updates against the existing key, so rotating it would break updates for current users. The safe order is to store the same key in the environment, verify it, and only then delete the repository-level secret.

- The updater signing key must be stored as KLADDE_UPDATE_SIGNING_KEY in the GitHub environment release-signing, with its password stored as KLADDE_UPDATE_SIGNING_PASSWORD if one is set.
- The release-signing environment must be restricted to protected main before the first production release.
- The old repository-level copy of the signing secret should be removed only after the environment copy is verified.
- Existing Kladde installations depend on retaining the same updater signing key.
